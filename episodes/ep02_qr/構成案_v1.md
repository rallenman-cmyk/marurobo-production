想定尺：**約21分**（各章は増減可）

## 0．先にやったこと：基準のQRを実際に作って壊してみた

構成を机上で考える前に、基準候補のQRを実際に生成しました。ソフトの読み取りライブラリ3種（zxing-cpp / OpenCV / ZBar）で、遮蔽をいろいろ試しています。
**これはPC上のシミュレーションです。スマホ実機での結果ではありません。** 本編で使う結果は、必ず実機で撮り直します。ただ、構成の軸を決めるには十分な、はっきりした傾向が出ました。

### 基準のQR（提案）
- 文字列：`MARU ROBO`（英大文字＋空白なので英数字モードで入る）
- **バージョン1（21×21マス）・誤り訂正レベルH**
  - 中身の箱（コードワード）が9個、**復元用の箱が17個**。1個の箱は8マスです。
  - つまり**模様の中のデータの約3分の2が「直すための予備」**です。これが冒頭の強い掴みになります。
- 同じ文字列をレベルLにしても**同じ21×21のまま**です（中身19個・予備7個）。
  - 「サイズを変えずに訂正レベルだけを比べる」ことができます（引き継ぎにあった「レベルを変えるとサイズも変わる」問題を回避できる）。
- 注意：バージョン1には位置合わせパターン（アライメントパターン）がありません。この部品は、大きいQRを見せるときに一言触れる扱いにします。

![構造](fig1_anatomy_H_vs_L.png)

### シミュレーションで分かったこと（構成の軸になるもの）

| 試したこと | 壊れた箱の数 | 結果（3ライブラリ） |
|---|---|---|
| 右下を8×8マス隠す（面積の15%） | 8 | **読める** |
| 右下を9×9マス隠す（18%） | 12 | 読めない |
| 中央に7×7マスのロゴ | 7 | **読める** |
| **点の汚れ12マスだけ（面積の3%）** | 12 | **読めない** |
| 目印の中心を3×3マスだけ隠す | 0 | **読めない** |
| **中身の箱9個のうち8個を消す** | 8 | **読める** |
| 中身の箱9個をすべて消す | 9 | 読めない |
| レベルLで右下5×5マス | 5 | 読めない（Hなら読める） |

![実験](fig2_experiments_V1H.png)

全位置への総当たり（3〜8マス四方、白・黒、計約6,000パターン）の結果です。目印と形式情報に触れない遮蔽では、
- **レベルH：壊れた箱が8個以下なら必ず読め、9個以上なら必ず読めない**（3ライブラリすべてで同じ）
- **レベルL：zxing・OpenCVは3個まで、ZBarは2個まで**（ここでアプリ差が出る）

**→ 決め手は「面積」ではなく「壊れた箱の数」です。** 8 ÷ 26 ≈ 31% が、公式の「約30%（コードワード単位）」の正体です。この結果は、デンソーウェーブの「面積の30%なら必ず読める、ではない」という説明とも一致します。

ほかの所見：
- **目印は直せません。** 小さく隠しただけで読めなくなります。「見つける段階」と「直す段階」の違いを、そのまま実験で見せられます。
- **白い余白**：きれいな画像では、余白0マスでも、周りにノイズがあってもほぼ読めました（OpenCVだけ余白0＋ノイズで失敗）。
  → 「余白がないと読めない」という劇的な失敗は**再現しない可能性が高い**です。実機の実験次第で扱いを決めます（後述）。

## 1．引き継ぎ案から変えた大きな点

### ① 冒頭の謎を「大きく隠しても読めるのに、小さな汚れで読めない」にする
「欠けても読める」だけだと「まあ、そういう機能でしょ」で終わりがちです。
**8×8の大穴はOKで、12個の点はNG**という逆転を後半の山場にします。そうすると、仕組みを知らないと説明できない謎になります。
冒頭では「欠けても読める→でも限界がある」を見せます。点の逆転は5章まで取っておきます。

### ② 舞台Bは「QRの中」ではなく「スマホが見ている像の中」
引き継ぎの注意点（復元を、紙の模様が物理的に直るように描かない）を、世界設定で解決します。
- 入口：スマホの画面を通り抜けてQRに入ります。中の世界は**読み取り機が見ている像**です。
- だから中の世界で箱がホログラムとして復元されても、紙は一切変わりません。
- 卓上（現実）に戻ると、QRは欠けたままです。この対比が自然に生まれます。

### ③ 8マス＝1個の「箱」を、映像の基本単位にする
引き継ぎでは「情報のまとまり」と曖昧でした。これを**8マスで1つの箱（荷物）**として3D化します。
- 中身の箱＝青、予備の箱＝橙です。
- 欠けた箱は灰色の抜け殻になり、復元された箱は半透明で光ります。
- イヤホン企画で検討していた「まるロボが荷物を運ぶ世界観」とも、自然につながります。
- 「壊れた箱の数で決まる」「点の汚れは箱をたくさん壊す」が一目で分かります。

### ④ 誤り訂正の説明を「1つの手がかり→2つの手がかり」の2段にする
引き継ぎの「合計は10」の例を発展させます。実際のリード・ソロモン符号の考え方（シンドローム）を、整数で素直に縮小した形です。比喩と本物がずれません。

1. **隠れた場所が分かる場合**：2・？・3、合計10 → 5。手がかり1つで1か所が戻ります。
2. **汚れて別の値に化けた場合（場所が分からない）**：2・**7**・3
   - 合計（10のはず）→ 12：**どこかが2ずれている**ことは分かります。でも、どこかは分かりません。
   - そこで2つ目の手がかりを使います：**1倍＋2倍＋3倍の合計**（2+10+9＝21のはず）→ 25：ずれは4。
   - 4 ÷ 2 ＝ **2番目**が2ずれている → 7−2＝5。場所と量が両方決まります。
3. **嘘をついた箱1個を直すには、手がかりが2つ必要。**
   → 予備17個で直せるのは8個（残りの1個は「本当に直せたか」の確認用）。
   - 実際のQRは、足し算の代わりに0〜255の中で循環する特別な計算を使います（名前：リード・ソロモン符号）。
   - 「同じ考え方を、もっと強力にしたもの」と言える範囲にとどめます。

さらにこれが5章の謎の答えになります。**点の汚れは、場所の分からない嘘を12個の箱にばらまく → 手がかりが足りない。** 説明が実験に直結します。

### ⑤ 歴史は終盤の独立章にせず、「なぜこの形？」の場面に分散する
終盤に2分の歴史章を置くと、手描きの盛り上がりの後で熱が下がります。
- 3つの目印の比率 → 2章で「なぜこの形？」として一言。
- 汚れに強くした理由（工場・現場） → 4章の導入で「なぜ予備が必要？」として一言。
- 普及・特許 → 結びで30秒。
- サムネ5案を主にする場合は別構成が必要、という引き継ぎの判断はそのまま維持します。

### ⑥ ロゴは「わざと壊している」
センターロゴの疑問（参考動画Aのコメント）への答えです。ロゴの下にもちゃんと模様があります。読み取り機は、ロゴを汚れとして扱って直しています。**予備を「ロゴのために使っている」**、つまり訂正能力を前借りしているので、汚れへの強さは減ります。

## 2．全体構成（約21分）

流れ：**隠す→読める→（でも限界）→ 中に入る → 見つける → 読む → 直す → 限界ゲーム → 手描き → 最初に戻る**

### 冒頭　0:00〜1:10　「欠けたのに読めた」
- 卓上（舞台A）。スマホでQRを読むと「MARU ROBO」と出ます。
- 右下に黄色い付箋 → 読めます。もう一回り大きい付箋 → 読めません。
- （オプション）付箋の下は、実は**文字が書いてある場所そのもの**です。中身の箱は右下に集まっています。
- ナレ方向：「隠したのは、ちょうど文字が書いてあるあたり。なのに、文字は消えなかった。」
  「この模様に詰め込まれた情報のうち、文字そのものは3分の1ほど。残りは"壊れたとき用の予備"なんです。」
  「でも、予備にも限界がある。どこまで耐えて、どこで力尽きるのか。中に入って確かめます。」
- まるロボ：付箋→画面→付箋と視線を往復させます。読めなかった瞬間に一歩下がります。
- タイトル。

### 1章　1:10〜3:30　中に入る：「この白黒には何が入っている？」
- **見せ場1：** スマホの画面にカメラが寄り、画面を通り抜けると、白黒441マスの大地になります。まるロボが降り立ち、カメラは大きく引いて全体を見せます。
- まるロボが歩くと、地面が3種類に色分けされていきます：**赤＝目印／青＝中身／橙＝予備**（＋紫の小さな帯＝形式情報）。
- 中身の青い箱の上に「M・A・R・U・…」と浮かびます。**中身はこの9文字だけ。**
- 引き継ぎのコメント疑問への回答：「URLのQRも、中身はただの文字。サイトを開くのはアプリの仕事。」
  （卓上で、URLのQRを読む→ブラウザが開くまでを5秒で見せる）
- 橙の箱の広さを見せて「残りの大部分は予備」→ 1章の終わりで「じゃあ、どう使うの？」と次へつなぎます。

### 2章　3:30〜6:30　見つける：「スマホはどこから読み始める？」
- **見せ場2：** 3つの大きな四角の真ん中に、まるロボが立ちます。目からスキャン光線を出して四角を横切ると、**黒白の幅が1:1:3:1:1**のリズムになります。
  光線をどの角度で通しても同じリズムになる → 傾いていても回っていても見つけられる。地面ごと傾く・回るカメラで体感させます。
  - 歴史の一言：「印刷物にほとんど出てこない比率を選んだ」（**要一次資料確認**）
- 3つの四角の位置関係で、向きが決まります（欠けた角が右下）。
- **タイミングパターン：** 目印どうしをつなぐ白黒交互の点線＝マスの物差し。まるロボが点線の上をぴょんぴょん渡り、マスの間隔を数えます。
- **形式情報（紫）：** 訂正レベルとマスク番号を書いた小さな札が**2か所に同じもの**として置いてあります。「ここにも予備がある」。
- **マスク（30秒の寄り道）：** マスクを外した生の模様を見せます。偏った塊ができて、目印に紛らわしい模様が生まれます。上から決まった柄を重ねてならす、と短く説明します（8種類から選び、番号を紫の札に書く）。
- **白い余白：** 世界の外周をまるロボが歩きます。「ここから先はQRではない、という岸」。実機の実験結果次第で扱いを決めます（§4参照）。
- **実験の差し込み：** 目印の中心だけを小さな付箋で隠す → **読めない。** 「大きく隠しても平気だったのに？」
  → 「目印は"見つける係"。ここを失うと、直す以前に、QRがどこにあるか分からない。」
- 大きいQR（バージョン2以上）を一瞬見せて、「大きいQRには、ゆがみを補正する小さな目印も増える」と一言だけ触れます。**実際に存在するモデルで見せる**ことを徹底します。

### 3章　6:30〜8:30　読む：「白黒がどうやって文字になる？」
- まるロボが右下から、**2列幅でジグザグに**登っていきます。通った8マスが持ち上がり、1つの箱になります。
- マスクの柄を外すと、箱の中の0と1が確定します。
- 中身の箱を並べると「MARU ROBO」になります（2文字ずつ組で入っていることは図解で一瞬）。
- 全部を追わず、最初の2箱だけ丁寧に、残りは早回しにします。
- 「では、この箱がいくつか壊れていたら？」→ 4章へ。

### 4章　8:30〜13:00　直す：「消えた情報をどう戻す？」（中心章）
- 導入：「QRは工場の部品管理のために生まれた。油や傷は当たり前の現場」（**要一次資料確認**）→ だから予備を入れた。
- 舞台は**落ち着いた図解空間**（白背景・大きな数字）。まるロボは数字の横に立ち、視線で比較対象を示します。
  1. 2・？・3 ＋「合計10」→ ？＝5。（隠れて見えない＝場所が分かる）
  2. 「でも汚れは"隠す"んじゃなくて"嘘をつく"」：2・7・3 → 合計12。ずれは分かるけど場所が分からない。まるロボが3つの数字の前を行き来して首をかしげます。
  3. 2つ目の手がかり「1倍・2倍・3倍の合計」→ ずれ4 → 4÷2＝2番目 → 5に戻ります。
     **天秤／メーター2本**の針が振れる3Dオブジェクトで、「ずれの量」と「場所」が同時に読める瞬間を作ります。
  4. 整理スライド：**嘘1個を直すには手がかり2個。** MARU ROBOのQR：予備17個 → 直せるのは8個。
  5. 名前の紹介はここで初めて：「リード・ソロモン符号」。CD・宇宙探査機などにも使われる、と一言（**要確認**）。
- **見せ場3：** QRの世界に戻ります。右下8×8が灰色に抜け落ちた大地です。橙の予備の箱たちから光の線が伸び、抜けた8個の箱がホログラムで組み上がります。浮かぶ文字は「MARU ROBO」。
  ナレ：「紙の上の模様は欠けたまま。直ったのは、スマホの中の情報です。」

### 5章　13:00〜16:30　限界ゲーム：「では、どこまで隠せる？」（後半の山場）
- 形式：まるロボと視聴者で「読める／読めない」を予想 → 実機で読む → 中の世界で「壊れた箱の数」を答え合わせ。テンポよく繰り返します。
  ルール表示（画面隅に常駐）：**壊れた箱 8個まで**
  1. 右下8×8 → ○（8個）／9×9 → ×（12個）。わずか1マス分の差が勝負を分ける。
  2. **中身の箱9個のうち8個を消す → ○。** 「文字が書いてある場所の9割を消しても読める」
  3. **点の汚れ12個（面積3%） → ×。** 一番の逆転。
     中の世界で見ると、12個の点がそれぞれ違う箱に当たっていて、12個の箱が嘘をついている。
     ナレ：「大事なのは、どれだけ隠したかではなく、いくつの箱を壊したか。」
  4. **中央ロゴ → ○。** ロゴを半透明にすると、下に模様が続いています。（**見せ場4**）「ロゴは"わざと壊している"。予備を前借りしているだけ。」
  5. **レベルLとH：** 同じ文字・同じ大きさの2枚を並べます。中身の箱と予備の箱の比率が違う（19:7 vs 9:17）。Lは5×5で×、Hは8×8でも○。
     「予備を増やせば強くなるけど、そのぶん中に入る文字は減る。」
  6. 整理スライド：「約30%」の正体＝箱26個のうち8個 ≈ 3割。面積の約束ではありません。
- アプリ差は脚注レベルで一言にとどめます（「アプリによって、粘り強さが少し違います」）。

### 6章　16:30〜18:40　手描き：「手描きでも、本当に読める？」
- 方眼紙に21×21を描き写します（早回し＋3Dでマスが並ぶ様子と対応）。
- 手描きのガタガタ・はみ出しも、「ちょっとした嘘」として直される → これまでの理解の確認になります。
- **中身は最後まで伏せた別の短いメッセージ**にします（案：`MATANE`、`ARIGATOU` など。英数字なら8文字程度までレベルHのバージョン1に収まる）。
- まるロボが結果を待ち（間）、読めたら小さく跳ねます。
- （実機での成功は未検証。描く大きさ、ペン、紙の条件をテストしてから決める）

### 結び　18:40〜20:30　最初に戻る
- 冒頭と同じ構図・同じ付箋。同じ行動を、まるロボがもう一度します。
- 今度は、読み取りの一瞬に重ねて**3段階**が透けて見えます：**見つける（赤）→ 読む（青）→ 直す（橙）**。
- 30秒の背景：開発から普及まで（規格の公開・特許の扱い）（**一次資料確認後に台詞化**）。
- 最後の一言（方向）：「白黒の中には、中身だけじゃなく、見つけてもらうための目印と、壊れたときのための予備が入っている。だから欠けても読める。でも、壊れた箱が予備の半分を超えたら、もう戻せない。」
- 締め：サムネのQRも本物です（実機で検証済みなら）→「読んでみて」。

## 3．まるロボの演出方針

**台詞なし**（ナレーションと分担）を推奨します。そのぶん、**動作の意味を固定した「語彙」**を持たせ、毎回同じ意味で使います。

| 動作 | 意味 | 主な使用場面 |
|---|---|---|
| 目からスキャン光線 | 「読み取り機が今ここを見ている」 | 2章の目印、3章のジグザグ |
| 2点を交互に見る | 原因と結果をつなぐ | 冒頭、5章 |
| 一歩下がる／首をかしげる | 予想外 | 冒頭の失敗、点の汚れ |
| アンテナの先が点灯 | 気づいた・分かった | 4章の2番目が判明する瞬間 |
| 箱を体で押して並べる | 情報を運ぶ（腕がなくても成立） | 3章 |
| じっと待つ（画面の間） | 視聴者にも予想させる | 5章、6章 |
| 小さく跳ねる | 成功 | 6章 |

- 遮蔽板を操作する装置は使いません。**付箋は、画面外の"手"なしで、カットで置かれている状態から見せる**のが一番シンプルです（実写／卓上3Dともに）。
- 世界の中でのまるロボは「読み取り機の代わりの視点」です。比喩の対応：まるロボ＝読み取りの処理、地面＝カメラが写した像、箱＝コードワード。この対応を1章で一度だけ明言します。

## 4．色と見せ方のルール（3D・図解共通）
- 赤＝目印／緑＝タイミング／紫＝形式情報／**青＝中身**／**橙＝予備**／灰の抜け殻＝壊れた箱／半透明の光＝読み取り機内で復元された箱
- 卓上・巨大QR・図解は、すべて**同じMARU ROBOのQR**（fig1の配置そのまま）を使います。どの場面でも「右下＝中身」が一致します。
- 白い余白：実機で「余白なし＋模様の多い背景」で読みにくくなる例が再現できれば、実験として見せます。再現できなければ、2章で「規格の約束（四辺に4マス分以上）」として20秒にとどめます。**できない失敗を演出で作りません。**

## 5．次に必要な確認・実験

**実機実験（最優先）**
- iPhone標準カメラ／Android（Googleレンズ等）／LINEなど、2〜3アプリ × 上記8条件。
- 条件を正確に作るため、**欠けた状態をデータで作って印刷した版**（`sim/` のスクリプトで生成可）と、**実物の付箋を貼った版**の両方を試します。
- 余白：0・1・2・4マス × 背景（白、柄物、文字だらけ）。

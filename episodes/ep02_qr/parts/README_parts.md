# QRコード回　編集用パーツ（2026-11-09）

台本の言い回しが変わっても使えるよう、構成（章・場面・実験）だけに合わせて作ったパーツです。
台本はv0.6（レビューツールの最新版）が前提です。

## 1. QRのデータ一式　`qrdata/qr_assets.json`
3D・図・印刷・実験は、すべてこのファイルを元にします。
- 基準のQR「HELLO」（V1-H・マスク2）
- 比べる用の「HELLO」（V1-L）
- 手描き用の「MATANE」（V1-H）
- マスの役割（目印・物差し・読み方の札・中身・予備）、箱（8マス）ごとのマス、読む順のジグザグ
- 柄を重ねる前の模様（S14）、0と1の区切り（S19：0010／000000101／HE／LL／O／終わりの印）
- 実験11条件：変えたマス・壊れる箱の番号と数・シミュレーションの結果

| 実験 | 壊れる箱 | 予想 |
|---|---|---|
| まるロボが乗る（体の楕円、1マス0.13m、中心16.5マス目） | 6 | 読める |
| 一歩踏み込む（0.40m内側） | 10 | 読めない |
| 目印の真ん中に3×3の箱 | 0 | 読めない（見つけられない） |
| 中身の箱8個消し／9個消し | 8／9 | 読める／読めない |
| 白いマスにしずく12か所（全部別の箱） | 12 | 読めない |
| ロゴ7×7／ロゴ＋しずく1つ | 8／9 | 読める／読めない |
| 右下に5×5の箱：レベルH／レベルL | 4／4 | 読める／読めない |

**台本に反映が必要な数字（次の版でまとめて直します）**
まるロボの体の形で計算すると、壊れる箱は「乗る」が6個、「一歩踏み込む」が10個になりました。今の台本は四角で計算した8個・14個のままです。対象は28-02・30-01・30-03・32-06です。実機の結果が出てから確定します。

まるロボの大きさを1マス0.13mにしたのは、乗っても読めて、一歩踏み込むと読めなくなる組み合わせを探した結果です。立つ位置を前後左右に0.25マスずつずらしても、ほぼ同じ結果でした（乗る：9通り中9通り読める／踏み込む：9通り中8通り読めない）。

## 3. 3Dの大地（舞台B）　`blender/qr_world.py`
Blender 4.3.2用です。こちらでEEVEEの試し描きができました（`blender/previews/`）。
- 441マスを1つずつの物として作ります。1マス1.5m、まるロボが1マスに立てる大きさです。
- 8マスごとに「箱」の親があり、持ち上げる・落とすは親を動かすだけです。
- 色は「物の色」で切り替え、コマごとにキーを打てます。
  - 白黒のまま
  - 役割の色分け：目印＝赤、物差し＝緑、読み方の札＝紫、中身＝青、予備＝橙
  - 壊れた箱＝灰の半透明
  - 復元した箱＝水色の半透明で光る
- 余白は白い岸で、その外は暗い床です（作り物の世界なのでC案の光）。
- `qr_parts_pc.zip`：PCの `C:\marurobo\marurobo_tools\` の横に展開して使います。
  - 試し描き：`blender -b -P qr_world.py -- --preview out.png --view hero --state roles`
  - `--view`：hero／top／low　`--state`：none／roles／lift／restore

まだ入っていないもの：
- まるロボ：PCのmaru_opening.blendを読み込んで置きます。
- 卓上の舞台A
- カメラの動き
- 光の作り込み

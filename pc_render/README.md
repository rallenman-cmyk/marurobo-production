# PC の描画係（pc_render）

ユーザーの PC に描画係（`agent.ps1`）が 1 つ常駐し、依頼を **1 件ずつ順に** 描く。各回のセッションは zip を手渡しせず、依頼を出すだけ。

## 各回のセッションの使い方
1. 今までどおり、その回の `pc_kit/make_kit.sh` で zip を作る（手順 `run_pc_render_epXX.ps1` は今のままでよい）。
2. 頼む：`python3 pc_render/request.py <zip> --ps1 run_pc_render_ep05.ps1 --name ep05_v3 --order 5 --session 🤖05掃除機`
   - 一部のカットだけ直すとき：`--only S10a,S11a` を付ける（**短い直しは、全部描きより先に描かれる**）。
   - zip は枝 `pc-kit/<id>` に入る（main の枝は重くしない。90MB まで。動画・声は入れない）。依頼票は `pc_render/queue/<id>.json`。
3. **終わったら、🖥PC描画の係のセッションから send_message で知らせが来る。各回のセッションは、自分で見回らない**（2026-11-15 ユーザー「係が指示する感じにしたい」。1 時間ごとの見回りの予約は入れない・入れてあれば消す）。頼むときは `--session` に自分のセッション名を必ず入れる。頼んだら、係のセッション（🖥PC描画の係）に send_message で「<id> を頼みました」と一言送る（係が見回りを始める合図）。
   - 自分で確かめたいとき（ユーザーに聞かれた、など）だけ：`python3 pc_render/status.py <id>`。
4. 知らせが来たら、Google ドライブ `marurobo_render/<回_版>` から受け取る（`scripts/drive_watch.py`）。ドライブへの上がりきりは少し遅れることがあるので、本数がそろっているか数えてから組み立てる。「そろわなかった」の知らせなら、記録の最後の行を読んで、直して頼み直す。
- ユーザーに「貼ってください」「終わったら知らせてください」と頼まない。
- 描く細かさは、何も付けなければ 24 で頼まれる（決まり。手順の既定が 48 のままでも 24 で描く）。変えるときだけ `--samples` を付ける。
- 取り消し：`pc_render/queue/<id>.json` を消して push。描いている途中でも、3 分ほどで止まる（2026-11-16）。
- **同じ版の名前（同じ出力フォルダ）で描き直すときは、必ず `--fresh` を付ける。** 付けないと、前に描いた絵が「できている」と見なされて、描き直されない（古い絵が混ざる）。`--fresh` は、`--only` のカットの分（無ければフォルダごと）の前の絵を捨ててから描く。版の名前を新しくするなら要らない。
- 依頼を出し直すときは `--replace <前の id>` を付ける（前の依頼票を消して置きかえる。描いている途中なら止まる）。request.py が、同じ名前の二重の依頼と、--fresh の付け忘れ（同じ出力フォルダ）を見つけたら止める。
- 係のセッションだけ：`pc_render/control.json` の restart_token を書きかえて push すると、描画係は描いている途中でもいったん止まり、新しい版に入れ替わって続きから描く（描画係を急いで直したいとき用。描きかけの 100 コマ分だけ描き直しになる）。
- 順番：短い直し（--only あり）→ `--order` の小さい順 → 受付の順。待っている全部描きは 2→3→4→5 の順（`--order` に回の番号を入れる）。`--order` は 1 以上（0 は「指定なし」で最後に回る）。

## 描画係のしくみ（agent.ps1）
- 2 分ごとに GitHub から取る → 依頼票を並べる → 先頭の 1 件：枝から zip を取り `C:\marurobo` に広げ、`--ps1` の手順を走らせる（そろわなければもう 1 回）。
- 結果は枝 `pc-render-status` の `done/<id>.json`（state・分・記録の最後の行）と `agent.json`（いまの様子）。
- 手で始めた描画が動いていたら、止めずに終わるのを待つ。`agent.ps1` が新しくなったら、次の合間に自分で入れ替わる。
- はじめ方（ユーザー向け）：`はじめに.md`。

## 速さの工夫（入れた。2026-11-15）
- **同時本数を測る**：最初の全部描きのとき、長いカット（1000 コマ以上・手つかず）で 1・2・3・4 本同時を順に試し、一番速い本数を `C:\marurobo\pc_workers.json`（枝 pc-render-status にも写し）に書く。測るのに描いた分は本番にそのまま使う。以後はその本数で描く（依頼で `--workers` を付けたときはそちら）。測り直すときは、PC のそのファイルを消す。
- **小さな直しは、大きな直しの途中でも先に描く**（2026-11-21、描画係 ver 11）：並べ方は「小さな直し（3000 コマまで）→ 大きな直し → 全部描き」。いま描いているのが全部描きでも大きな直しでも、小さな直しが来たらいったん止めて先に描き、終わったら続きから。
- **割り込むのは小さな直しだけ**（2026-11-16）：3000 コマ（約 2 時間半）までの直し。それより大きな直しは、いま描いている 1 件が終わってから、ほかの全部描きより先に描く。量は request.py が zip の手順から数えて依頼票（frames）に入れる。
- **短い直しの割り込み**：全部描きの途中に `--only` の依頼が来たら、全部描きをいったん止めて直しを先に描き、終わったら続きから（できている所は残る。止めたときに描きかけだった 100 コマ分だけ描き直し）。
- 手で始めた描画を待つ間も、描画係は回り続ける（自分の入れ替え・依頼票の読み直しができる）。入れ替えの前に書き方を点検し、誤りがあれば今のまま動く（`agent_error.json` に出る）。

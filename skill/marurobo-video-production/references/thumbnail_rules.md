# サムネ作成のルール（2026-11-20〜21 ユーザー決定。4本目で承認された 3 枚から）

サムネを作るときは、どのセッションも、このルールで作る。作る前にこのファイルを読む。
例と理由：`episodes/ep04_robot/thumbs/サムネのリサーチ.md` の「決まった 3 枚の構図で意識したこと」。
道具：`episodes/ep04_robot/thumbs/thumbs04.py`（`band`・`big_card`・`q_mark`）。字は `episodes/ep02_qr/thumbs/thumbs_v3.py` の関数も使う。

## 順番
1. 同じ話で伸びた動画を 20 本以上調べる（再生数・登録者数・サムネの画像を並べて見る）。
2. ユーザーの参考（前に承認されたサムネ・建物の深層 @tatemono-shinsou）と並べる。
3. 案を 2〜3 枚作る。
4. 下の「点検」を全部やる。
5. 見せる。
直しを受けたら `references/feedback_log.md` に書き足し、新しい決まりはこのファイルにも足して push する。

## 構図のルール
1. **型**：上に黒い帯（高さの 17%）を置き、白い極太字（Noto Sans JP 900）で 1 行の問いを書く（「なぜ〇〇は〜のか？」「〇〇が〜するとどうなる？」）。物の名前は黄色、おかしな所・結果は赤。帯の外に大きな字は置かない。帯の下は明るく清潔な 3D の絵（暗い絵にしない）。
2. **主役は話の物そのもの**（見ただけで何の話か分かる物）。大きく、正面向き。
3. **1 枚で言うことは 1 つ。物は少なく。**形は次の 3 つから選ぶ。
   - 左右の比べ：左右を同じ場所・同じ物にして、違いを 1 つだけにする（例：人が押す ✓／まるロボが押す ✕）。
   - 前→後：左に前、真ん中に赤い太い矢印、右に結果（結果を隠すなら赤い ？）。
   - アップ：押す・使う直前の一瞬を近くから（人の顔・手・物）。
4. **印はだれでも分かるもの**：通った＝緑の ✓、だめ＝赤の ✕、分からない＝赤い ？、注目＝赤い丸・赤い矢印。本編を見ないと分からない約束ごとは使わない。
   - 左右の比べでは、比べている物そのもの（お互いのイヤホンなど）を赤い丸で囲む。間に赤い ？ を浮かべない。？ は前→後で結果を隠すときだけ（2026-11-20 1本目「1のサムネでハテナはやめて、お互いのイヤホンを赤丸で囲って」）。赤い丸は白いふちつきで、目にかけない。
5. **答えは見せない。**問いだけを見せ、答えは本編で明かす。
6. **絵の中の字**（画面の札など）は 2 行まで、1280 幅で字の高さ 35px 以上。絵の AI には画面や欄を無地で描かせ、札・印・字はこちらで重ねる（AI に字を描かせない）。→ 2026-11-23 から、字は GPT Image 2 に絵と一緒に描かせる（SKILL.md §9 の 4）。数で決めた値（字の高さ・帯の幅など）は、描けた絵を thumb_measure.py で測って確かめる。
7. **重ねない**：札・印・矢印を、人の顔・まるロボ・ほかの印・帯の字にかけない。右下（再生時間が出る所）に大事な物を置かない。
8. **まるロボは本物の形**（一つ目・アンテナ・脚と靴・腕なし・口なし）。AI が腕・口・怒った目を描いた絵は使わない。

## 数で決めた値（2026-11-21 ユーザー「文字数と黒帯のサイズをリサーチ元からしっかり調べて」「背景とのコントラストも」）
建物の深層の 16 枚を 1280×720 で数えた値。道具 `scripts/thumb_measure.py`（band・ink・pic）で、こちらの案も同じに数えて、下の幅に入れてから見せる。`thumbs04.py` の `band_text`・`grade`・`big_card` がこの値で描く。
| 何を | 建物の深層 | 決まり |
|---|---|---|
| 黒い帯の高さ | 133px（18.5%）。16 枚とも同じ | 18.5%。帯の色は真っ黒 (0,0,0) |
| 帯の字の高さ | 102〜104px（14.2〜14.4%）。長い字だけ 82〜85px | 14.4%（帯の 78%）。上下の余白 13〜16px |
| 帯の字の幅 | 画面の 91〜99% | 92〜97%。足りなければ字を横に詰める（0.80 まで）、それでも入らないときだけ小さく |
| 1 行の字数 | 10〜17 字（多くは 12〜14 字） | 14 字までを目安。16 字をこえるなら言葉を削る |
| 字の詰め・太さ | 字の箱の中の字の割合 0.45〜0.54、線の太さは字の高さの 18% | 字の間を詰める（-0.07）、同じ色のふちを足して太く。ふちの別の色は付けない |
| 字の色 | 白 (255,255,255)・黄 (251,254,5)・赤 (248,3,3) | 同じ。物の名前は黄、おかしな所・結果は赤、ほかは白 |
| 帯の下の絵 | 色の強さ 68・明暗の差 62・鮮やかさ 0.29・明るさ 169（平均） | 絵の AI の絵が白っぽい・色が薄いときは、`grade` で鮮やかさ 0.27〜0.31・明暗の差 58〜72・明るさ 165〜180 に合わせる |
| 吹き出し・札 | 白い地・黒いふち（4px）・字は大きく | 白い地・黒いふち（1280 幅で 4px）・字は真っ黒の極太 |
- **短い問い・白っぽい絵のとき（2026-11-21 QR回の C）**：12 字の問いは字の高さ 14.4% のままだと幅が 92% に届かないことがある。そのときは横に少し広げて（1.15 倍まで）92% に届かせる。白っぽい水色の絵は、鮮やかさを 1 回（2 倍）上げても 0.22 にしかならなかったので、0.27 に届くまで少しずつくり返す（合わせて 3.5 倍まで）。鮮やかさを上げると、まるロボの白い体も少し色づくので、目で見て白く見えるかを確かめる（`episodes/ep02_qr/thumbs/thumbs_band.py` の `band_text`・`grade`）。
- **画数の多い字がつぶれないこと（2026-11-21 QR回の C「読めるの文字潰れてて読めないよ」）**：同じ色のふちで太らせる（字の高さの 1.8%）と、赤い「読」の中の線がくっついて読めなかった（赤は黒の地との明るさの差が小さく、つぶれが目立つ）。太らせをやめて 900 の書体だけにすると、320 幅でも読めた（字の濃さは 0.50 → 0.41）。字の濃さの数より、読めることを先にする。帯の字は、画数の多い字（読・識・機・議など）を 320 幅に縮めて、中の線が分かれて見えるかを目で確かめる。
- **帯の「?」（2026-11-21 1本目 L）**：帯の問いの「?」は半角にする（建物の深層と同じ背の高い形。全角の「？」は小さく、前が空きすぎる）。「?」の前は字の間を詰めない（詰めると前の字にくっつく）。ふちを足さないと字が 2px ほど低くなる（101px）ので、描いた字の高さを数えて 14.4% に合わせ直す（`episodes/ep01_earphone/thumbs/thumbs_ep01.py` の `band_text`）。
- 前のこちらの 3 枚は、帯 16.9%・字の高さ 10.6〜12.9%（建物の深層より 2〜3 割小さい）・字の濃さ 0.37（字の間が空いていた）・黄が少し橙・絵が白っぽく色が薄い（明るさ 201・鮮やかさ 0.16）で、「視認性が悪い」と言われた。

## 点検（見せる前に全部）
`scripts/thumb_measure.py` で数えて「数で決めた値」の幅に入っているか。そのあと 1280・320・210 幅に縮めて、次を確かめる。
- 問いと札の字が読めるか。
- 何と何を比べているか、一目で分かるか。
- 答えが出ていないか。
- 重なりがないか。
- まるロボの形が崩れていないか。
